# MedSense MVP

## Обновление к финальной защите 9 ноября 2026

В кабинет пациента и карту закреплённого пациента у врача добавлен «Помощник» / Assistant. Четыре темы: последние показатели, сводка за 14 дней, техника измерения и вопросы врачу. Источники доступны внутри панели. Кнопка опасных симптомов показывает срочную подсказку сразу, без ожидания сервера.

Это локальный справочный помощник по правилам, а не генеративный ИИ. API-ключ и платная подписка не нужны; показания стороннему ИИ не отправляются. Он не ставит диагноз, не подбирает лекарства и не меняет лечение. Беременность, послеродовой период и возраст до 18 лет исключены из общих правил. Перед расширенным тестированием тексты должен проверить врач.

Проверка: `npm test` — 27 тестов. Новые файлы: `assistant-service.mjs`, `tests/assistant.test.mjs`, `public/assistant.css`. Маршрут `POST /api/assistant` использует существующую авторизацию и доступ только к своему или закреплённому пациенту. История диалога не хранится; журнал фиксирует только открытие темы. Этот блок не означает, что новый помощник уже прошёл человеческое beta-тестирование.

Рабочий локальный прототип для Assignment 5. Пациент добавляет измерения, врач видит историю и оставляет отметку просмотра. Данные сохраняются в SQLite и остаются после перезапуска.

Версия 1.1 добавляет подготовку удалённого Beta-режима с отдельной базой, случайными индивидуальными паролями, запретом демо-входа и HTTPS-сессиями. Подробности в `REMOTE_TESTING.md`. Локальная демонстрация работает по прежнему сценарию. На момент подготовки пакета внешний туннель не запускался: требуется согласие на передачу тестового трафика через Cloudflare.

## Быстрый запуск на Windows

1. Установите Node.js 24 или новее.
2. В папке проекта выполните `npm ci`.
3. Выполните `npm start` или откройте `Start-MedSense.cmd` и оставьте окно работающим.
4. Откройте **http://localhost:4173** и выберите «Кабинет врача» или «Кабинет пациента» для входа с вымышленными демонстрационными данными.

Сервер создаст локальную SQLite-базу при первом запуске. Интернет нужен для начальной установки зависимостей. Локальное демо после установки работает без подключения.

Альтернативный запуск: `npm start` или `node server.mjs` из этой папки. Если адрес уже занят, сначала проверьте, не работает ли MedSense в другом окне. При необходимости задайте `PORT` перед запуском.

## Демонстрационные аккаунты

| Роль | Почта | Пароль |
|---|---|---|
| Врач | doctor@medsense.local | Doctor2026! |
| Пациент 001 | patient1@medsense.local | Patient2026! |
| Пациент 002 | patient2@medsense.local | Patient2026! |
| Пациент 003 | patient3@medsense.local | Patient2026! |
| Пациент 004 | patient4@medsense.local | Patient2026! |

Все исходные профили и измерения вымышлены. Профиль P001 начинает с повторного превышения демонстрационных порогов, P002 — с пропуска данных, P004 — с отметки просмотра. Во время технической проверки в P001 добавлены одно вымышленное измерение и демонстрационный комментарий.

Врач создаёт новые кабинеты через «Добавить пациента». Используйте псевдонимы и тестовые адреса, например `participant05@example.test`. Участник входит с указанными при создании почтой и паролем. Пароли хранятся в виде хеша, а исходное значение после создания не показывается. Новые кабинеты помечаются «Участник теста», начальные — «Демо».

## Что уже реализовано

- Вход с двумя ролями, серверные сессии и выход.
- Доступ пациента только к своим данным, врача — только к закреплённым пациентам.
- Ввод давления, пульса, времени и заметки с проверкой значений.
- Сохранение измерений, истории и комментариев в базе.
- График и средние значения за скользящие 14 дней.
- Список пациентов, поиск и фильтры по состоянию просмотра.
- Повторные демонстрационные превышения и пропуски данных.
- Изменение параметров правил в кабинете врача.
- Отметка просмотра с комментарием, видимым пациенту.
- Возврат карточки в очередь при появлении нового измерения.
- Экспорт истории пациента в CSV.
- Метрики активности и экспорт последних 60 событий за 14 дней.
- Казахский, русский и английский интерфейс, адаптивная компоновка. Язык можно выбрать на экране входа и в каждом кабинете.

Приложение не обновляет кабинет врача в фоне: после добавления измерения из другого кабинета нажмите «Обновить» в карточке или перейдите в раздел «Пациенты». Для двух ролей одновременно откройте обычное и приватное окно браузера. Две вкладки одного браузерного профиля разделяют сессию.

## Сценарий демонстрации на защите

1. Войдите врачом, покажите список пациентов и разные флаги.
2. Откройте карточку P001, покажите график и таблицу.
3. Сохраните комментарий «Тест интерфейса: история просмотрена» и отметку просмотра.
4. Выйдите. Войдите пациентом P001 и покажите комментарий врача.
5. Добавьте вымышленное измерение, например 128/82, пульс 72, с текущим временем.
6. Войдите врачом: карточка снова требует просмотра, в истории есть новая запись.
7. Выгрузите CSV и откройте «Метрики MVP».
8. Покажите создание кабинета нового участника и возможность войти в него.

Не называйте демонстрационные события результатами пользовательского исследования. Для отчёта нужны отдельные тесты с людьми и протокол наблюдения.

## Как устроены правила

По умолчанию «Повторное превышение» появляется, если каждое из двух последних измерений за 72 часа достигает хотя бы одного тестового порога: систолическое от 160 или диастолическое от 100. Одиночное превышение не вызывает этот флаг. «Пропуск данных» появляется через 48 часов без измерений, для нового аккаунта — с момента создания. Врач может изменить пороги и период.

Это учебная логика отбора записей, а не клинически утверждённый алгоритм. Флаги не являются диагнозом, рекомендацией о лечении или системой экстренного оповещения. Значение «без флагов» означает только отсутствие этих двух условий и не оценивает здоровье.

Отметка просмотра привязана к версии истории. Новая запись снова открывает карточку для проверки. Сервер отклонит отметку, если во время просмотра пришли ещё не показанные врачу измерения. Длительный пропуск может снова потребовать внимания после истечения периода без просмотра.

## Данные и ограничения первой версии

База находится в `data/medsense.sqlite`. Во время работы SQLite может создавать соседние файлы `-wal` и `-shm`. Для резервной копии сначала остановите сервер и затем скопируйте папку `data` в приватное место. Не передавайте базу с данными участников вместе с исходниками для публичной сдачи.

Демо-профили создаются только при первом запуске пустой базы. Для новой независимой демонстрации можно задать другую папку через `MEDSENSE_DATA_DIR`. Это не удаляет прежние данные. Относительные даты начальных записей рассчитываются при создании базы, поэтому через несколько дней у старых демо-профилей появятся флаги пропуска.

Сервер слушает только этот компьютер. Входы и пароли демо-аккаунтов публичны по замыслу, база не зашифрована. Первая версия подходит для учебного теста интерфейса с вымышленными или согласованными обезличенными данными на контролируемом компьютере. Для клинической эксплуатации потребуются отдельные меры защиты, проверка медицинской логики и соответствия требованиям. Не открывайте этот сервер в интернет как готовую медицинскую систему.

В этой версии нет прямого Bluetooth-подключения Omron, Apple Health, Samsung Health, ОСМС, автоматической диагностики, SMS, биллинга или интеграции с клинической МИС. Ввод вручную проверяет основной рабочий процесс. Отметьте отложенные интеграции в границах MVP и дорожной карте.
