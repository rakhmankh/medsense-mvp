# Удалённый Beta тест MedSense

## Запуск

Дважды нажмите `Start-Beta-Link.cmd`. Программа запускает отдельную версию приложения на порту 4174 и создаёт временную HTTPS-ссылку через Cloudflare Quick Tunnel. Ссылка выводится в окне и сохраняется в `.local-beta/session.json`. Оставьте окно работающим, компьютер включённым и подключённым к интернету.

Индивидуальные логины и пароли доступны только в локальном файле `.local-beta/access.html`. Откройте его на своём компьютере. Каждому участнику отправляйте только его строку. Весь файл содержит доступ врача и других участников, поэтому его не следует пересылать целиком. Адреса вида `parent1@medsense.test` — логины, а не работающие почтовые ящики.

Подготовлены один кабинет врача, пять отдельных кабинетов пациентов и служебный аккаунт QA для технической проверки. Кабинеты участников изначально пустые. Служебный аккаунт QA обозначен как демонстрационный и не входит в количество подготовленных кабинетов участников.

## Как протестировать с телефона

1. Передать участнику HTTPS-ссылку, его логин и пароль.
2. Попросить открыть ссылку в Chrome или Safari на телефоне и войти.
3. Добавить вымышленное измерение 128/82, пульс 72. Не вводить настоящие медицинские данные в этом учебном Beta-тесте.
4. Врачу войти с отдельными данными, найти запись, посмотреть историю и оставить учебный комментарий.
5. Пациенту нажать «Обновить», чтобы увидеть комментарий.

Для проверки формы достаточно одного измерения. Для проверки динамики можно добавить несколько вымышленных записей с прошедшими датами. По мере проведения сессий код участника, время и подсказки заносите в протокол тестирования. Сам факт создания кабинета не означает, что человек завершил сессию.

## Что отличается от локальной демонстрации

- Используется отдельная база `.local-beta/data`. Локальная база `data` не публикуется и не переносится.
- Демо-кнопки входа скрыты, известные локальные пароли в удалённой базе не действуют.
- Индивидуальные пароли генерируются случайно и в базе хранятся в виде хеша.
- Сессии по HTTPS используют HttpOnly, SameSite и Secure cookie.
- API принимает только свой публичный Host и Origin; действуют ограничения попыток входа.
- Пациент видит только свои записи, врач — пациентов своего теста.
- Публичный доступ не открывает остальные папки или сервисы компьютера.

Cloudflare выступает HTTPS-посредником для запросов к приложению. Данные приложения остаются в локальной SQLite, но трафик проходит через инфраструктуру Cloudflare. Это ссылка для учебной проверки интерфейса с вымышленными данными, а не клинический сервис.

## Остановка и повторный запуск

Нажмите Ctrl+C в окне Beta. Программа остановит туннель и тестовый сервер. При повторном запуске адрес изменится, а пароли и сохранённые записи останутся. Передайте новую ссылку участникам.

Если программа сообщает, что уже работает, используйте прежнюю ссылку из `.local-beta/session.json`. Не запускайте вторую копию одновременно. Если окно закрыто, проверьте, что оно действительно завершило процессы, прежде чем запускать новую сессию.

Это временная публикация. Для постоянного адреса и работы при выключенном компьютере потребуется отдельное размещение сервера и базы. Доступность Quick Tunnel не гарантирована.
